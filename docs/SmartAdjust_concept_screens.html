Callouts and the requirements they implement

ScreenRequirementWhat the screen does
iDOL53 Ammonia1REQ-A-01, 02 Opened as the dol-sensors product, not as a Milesight converter: the app bar names the article and carries the UC501 revision underneath.
2REQ-A-04 Control first: power on and off as a toggle, restart as a separate action that keeps the configuration. At the top because a device that is off has nothing to read, so this is the first thing an installer needs.
3Newto add Last measured value read from the sensor over NFC, with the time it was read. No requirement covers this yet — REQ-A-05 lists identity, network and power values only.
4REQ-A-03 Revision with a plain verdict against the qualified list; an unqualified revision turns the row amber with the reason.
5REQ-A-10 Region as one row with the alternatives named. The channel plan is written with the region and is not shown.
6REQ-A-05 Supply state above battery level, battery labelled as backup, so a mains-powered unit reading 96 % is not mistaken for healthy when the supply is gone.
UC501 serial1REQ-A-04 Power and restart, in the same place on every device type.
2Newto add Decoded serial value with the raw response length beside it, so a failed exchange is distinguishable from a zero reading.
3REQ-A-07, 08 Named configuration on one row, opening the serial parameters, inside the same Device section every screen uses. Analog and pulse stay out while the standalone converter is out of scope.
EM500-CO2-T-H1REQ-A-04 Power and restart. Switching a battery sensor off is how it is stored or shipped without draining it.
2Newto add Three measured values side by side. A multi-parameter sensor needs all of them on the screen; one hero value would hide the others.
3REQ-A-10 Region changeable within the -915M band group.
4REQ-A-05 Battery as service life on a battery-powered sensor — the opposite meaning to the UC501 row, so the wording differs deliberately.
EM300-TH1REQ-A-04 Power and restart, as on every device type.
2Newto add Two measured values. The same card adapts to the number of parameters the sensor has.
3REQ-A-11 Region shown without a chevron: on EU hardware there is nothing to choose, so the row reports and does not invite a tap. No explanation is shown — an EU installer has no other region to pick.
Concept only. Where a screen and a requirement disagree, the requirement governs. Values are illustrative. The channel plan is written with the region and never shown to the user. The reporting interval is read only throughout — it is changed from the gateway. Showing the last measured value needs a new requirement in the app specification, and confirmation that each device exposes its latest reading over NFC.
